# Курсовой проект Itransition: Система управления запасами
## О проекте
Система управления запасами — это веб-приложение, позволяющее пользователям создавать и управлять пользовательскими списками товаров с гибкой структурой полей. Каждый список может содержать товары с динамически определяемыми полями (текст, число, логическое значение, дата). Пользователи могут полностью настраивать структуру своих списков и управлять товарами внутри них.

## Ключевые функции
- Аутентификация и авторизация пользователей (включая вход через социальные сети)
- Контроль доступа на основе ролей (Администратор / Владелец / Гость)
- Создание и управление списками товаров
- Динамические пользовательские поля для списков товаров
- Управление товарами на основе определенной структуры полей
- Комментарии и лайки
- Полнотекстовый поиск по спискам товаров
- Сортировка, фильтрация и постраничная навигация данных
- Комментарии в реальном времени с использованием WebSocket
- Адаптивный пользовательский интерфейс Angular с Angular Material
  
## 1. Назначение системы
Разработка веб-приложения для создания и управления пользовательскими списками товаров с динамической структурой полей. Система должна позволять пользователям самостоятельно создавать:

- Инвентарь
- Пользовательские поля
- Значения для этих полей
- Товары
- Пользовательский ID для товаров
  
## 2. Архитектура
Веб-приложение (клиент-серверная архитектура):

- Фронтенд: Angular SPA
- Бэкенд: Node.js + Express REST API
- База данных: PostgreSQL (реляционная база данных)
- Реализация в реальном времени: WebSocket (ws)
- Деплой: Netlify (фронтенд) + Render (сервер)
  
## 3. Функциональные требования
### Аутентификация
- Регистрация пользователей, включая вход через социальные сети
- Авторизация
- Администраторы имеют полный доступ
- Владелец (авторизованные пользователи) - доступ только к собственному инвентарю/товарам и инвентарям/товарам, к которым у них есть доступ на запись
- Неавторизованные пользователи - только для чтения
### Управление инвентарем
Пользователи могут:

- создавать инвентарь
- просматривать список своих инвентарей и инвентарей, к которым у них есть доступ на запись Редактировать
- удалить
- настроить
### Управление полями (динамическая структура)
- Пользователи могут:

- добавлять пользовательские поля в инвентарь
- удалять
Каждое поле содержит:

- название
- тип данных
Поддерживаемые типы:

- текст
- число
- логическое значение
- дата 
  
  Структура поля определяется пользователем.

### Управление товарами
Пользователи могут:

- создавать товар
- редактировать
- удалять
При создании товара:

- система отображает форму на основе созданных пользовательских полей
- тип ввода зависит от типа пользовательского поля
## 4. Архитектура данных
### База данных содержит:
- Пользователи — системные пользователи
- Категории — категории товаров
- Теги — теги для товаров
- Товары — коллекции (инвентари)
- Товары — товары в инвентаре
- Комментарии — комментарии к товарам
- Лайки — лайки к товарам
### Связи:

Товар → принадлежит пользователю (автору товара)

Товар → принадлежит категории

Товар ↔ имеет несколько тегов (многие ко многим)

Товар → принадлежит инвентарю

Товар → принадлежит пользователю (автору товара)

Комментарий → принадлежит пользователю

Комментарий → принадлежит инвентарю

Лайк → принадлежит пользователю

Лайк → принадлежит элемент

### Особенности модели:

Инвентарь определяет структуру полей (строка, число, текст, логическое значение, URL) с помощью *_label

Элементы хранят значения этих полей (string_1, integer_1, text_1 и т. д.)

customId — идентификатор пользователя элемента в инвентаре

version используется для оптимистической блокировки

элементы автоматически удаляются при удалении инвентаря (onDelete: Cascade)

один пользователь может поставить лайк только одному элементу
